## Summary

The milestone was opened to explain a contradiction: the dashboard read **+$1,296 logged P&L (Bot A)**
while the real Alpaca account was at **−14.34%**. It found the cause, fixed the measurement stack,
enforced the asset universe, remediated live risk-rule breaches, and got the bots reliably running with
alerting that actually fires. It did **not** deliver the entry-knob retune — see PARTIAL outcomes below.

## Key Accomplishments

- **Order-state resolution + realized P&L from actual fills, net of fees** (PNL-01 / PNL-02 / PNL-04).
  Every submitted order now reaches a recorded terminal state; closed trades carry fill-derived P&L.
- **Alpaca reconciliation + stale-trade backfill** (PNL-03 / PNL-05) — per-bot delta vs. real account
  P&L with a tolerance flag; a repair path for open-but-stale rows.
- **Universe hard-gate at all 5 entry sites + config-driven quarantine + dashboard visibility**
  (UNIV-01 / UNIV-02 / UNIV-03) — closed the TRUMP / FIL off-universe leak and made the effective live
  universe visible so a future leak cannot hide.
- **Per-symbol evidence (TUNE-02) found the root cause of the whole contradiction:** **395 of 655
  position-closed rows (60%) were external-exit sentinels written as `pnl = 0.0`, and the dashboard
  booked every single one as a LOSS.** That is the entire "+$1,296 logged vs −14% real equity" gap.
  The sentinel writer was fixed and the win-rate denominator corrected at 5 reader sites; the
  paper-trade gate moved 655 → 260 (delta exactly −395).
- **Runtime honesty (RUN-01 / RUN-02):** fixed `if not any_alive: return` — all-bots-down was the ONE
  state guaranteed never to alert, which is precisely why four dead bots went unnoticed. Bots A/B/C now
  run, alerts genuinely deliver (SES-confirmed), and the dashboard headline reflects reconciled numbers.
- **Prod risk-rule breaches remediated:** Bot B kelly 0.50 → 0.25 and max_position 0.10 → 0.05;
  **Bot E was configured to put 100% of bankroll into a single position — a 20x breach — now 0.05.**
- **Disarmed a loaded gun:** `scripts/backfill_trades.py` had carried an armed `--apply` since Phase 14
  that would have closed every HELD position with a fabricated loss (proven by execution). Fixed, and
  still unarmed.
- **Test suite 279 → 541**, zero new skips.

## Honest Outcomes — the two requirements that did NOT close

### TUNE-01 — **PARTIAL**

The quarantine + risk-rule fixes shipped. The **entry-knob retune did not.** The backtest engine models
exits as a flat −15% / +30% barrier while the live bot runs −8% plus an ATR trailing stop, so the
win-rate criterion had only **two possible values across all 12 live cells** and could not discriminate
between them — the sweep returned a negative result its own harness could not have falsified. Phase 17
located the real losses on the **EXIT** side, the one dimension the harness does not model. Tuning entry
thresholds was aiming at the wrong half of the system.
**Phase 21 (Exit-Stack Backtest Fidelity + Real Retune) is opened to fix engine fidelity and retune for real.**

### VERIFY-02 — **PARTIAL (scoped)**

All-time reconciliation **cannot close.** The 395 fabricated-zero rows contribute nothing to
`trade_log_pnl` while Alpaca's equity already contains their real outcomes, so the delta is a **fixed
level offset** — Bot A **$8,720.31**, Bot B **$1,610.22**, Bot C **$2,039.64** — unreachable forever
unless those rows are repaired.

**And the shipped backfill cannot repair them.** All 395 are `status='closed'` with `order_id IS NULL`,
while the backfill selects only `status IN ('open','submitted') AND order_id IS NOT NULL`.
**Recovery ceiling = 0/395.**

The honest path is the **anchored post-T0 window**, which opened **2026-07-14 07:18 UTC** and needs
**≥20 resolved trades per bot** before it can be evaluated.
**Dated follow-up:** not before **2026-07-28**, via `python scripts/e2e_verify.py --json`.
