<objective>
Lay the data + client foundation for order-state resolution: persist the Alpaca `order_id` (plus
`order_type`, `filled_qty`, `filled_avg_price`), allow rows to be written in a `submitted`
pre-terminal status, stamp `closed_at` on the new terminal order statuses, expose a DB read of
pending orders, and add a single-order fetch wrapper. These are the contracts the Wave 2 resolver
consumes.

Purpose: Root cause (PNL-04) is that `order_id` is discarded and rows land `open` at submit with no
fill confirmation. This plan makes order identity + type + fill data durable and queryable.
Output: migration 015, mirrored schema DDL, extended `src/db.py`, new `AlpacaClient.get_order`.
</objective>
