Purpose: this is the phase that asks, adversarially, whether any of phases 11-19 actually reconciles
against real money. The answer must be written down as **measurements**, not as claims. Three things go
into the file and they are all numbers somebody actually took:

1. **The E2E reconciliation report** — `scripts/e2e_verify.py`'s output, SELECT-only, run against prod

   offset, and the all-time row labelled `legacy: true` and **still breaching**.

   can *still* answer for. This is the number a human needs **before** being asked to authorize a write
   to production trade data.
3. **The measured paper-gate before/after** — because RESEARCH R1 proved the projected "655 → ~260"
   conflates two different bot populations, and a milestone about eliminating unverified numbers cannot
   close on one.

And then it **stops**. The backfill is fixed, tested, documented — and **left unarmed**, behind a
blocking human checkpoint. Repairing the 395 rows is a write to historical production trade data. It
requires explicit human authorization. Phase 20 plans it; Phase 20 does not do it.

**If the credentials for a run are not available, the file records `NOT_RUN` with the reason and the
exact reproduce command. It never records a guessed number.** An invented figure in an evidence file is
the precise defect this milestone exists to eliminate.
