<objective>
Build `scripts/e2e_verify.py` — the SELECT-only end-to-end check that **is** VERIFY-02's deliverable.

Purpose: the milestone's stated goal is *"the dashboard reconciles to real Alpaca equity."* Right now
it does not, by thousands of dollars, on every live bot — and Phase 20's job is to say so **honestly**,
with a number that means something. This script reports, per bot:

- the **windowed** verdict (post-`T0`, the period in which the fixed code was actually running, which
  contains **zero fabricated rows by construction**),
- the **resolution rate** post-`T0`,
- the **legacy offset** — the all-time delta at `T0`, surfaced next to the check with its
  authorization note, never hidden,
- the **all-time** row, labelled `legacy: true`, still breaching, exactly as it should,
- and the **measured** paper-gate before/after — because RESEARCH R1 proved the "655 → ~260"
  projection conflates two different bot populations, and this milestone exists to eliminate exactly
  that class of unverified number.

It is **SELECT-only**, with read-only enforced by **Postgres itself** (SQLSTATE 25006), not by
convention. It has **no `--apply`, no write flag, and no tolerance flag** — a CLI tolerance override is
a widening lever by another name.

Output: `scripts/e2e_verify.py`. Cases **12, 14, 16 go GREEN** (13 and 15 already passed).
