<objective>
The foundation RUN-01's fix stands on: the heartbeat table (in BOTH files), the notifier wrappers, the
alert-path self-check, the swallowed-error recorder, and the dashboard-side heartbeat readers.

Purpose: `src/notifier.py::send_alert` SWALLOWS every failure (`:47-61`). An unconfigured — or merely
mis-configured — SES therefore produces **a system that believes it is alerting and is not.** A silent
alerter and a silent bot are the same outage twice. And nothing outside the dashboard process can
currently distinguish "manager running, bots healthy" from "manager never started", because
`main.py:65-66` swallows that failure into a `_log.warning`. This plan builds the things that make both
conditions **visible**.

Output: migration 019 + its schema mirror; five notifier functions; two heartbeat readers.
No behavior changes in `bot_manager.py` yet — that is 19-03.
</objective>
