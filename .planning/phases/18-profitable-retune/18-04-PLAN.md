<objective>
Fix the win-rate denominator at **all three** sites, and add `AIPW_DB_READONLY=1`.

Purpose: the phase's own acceptance bar is `win_rate >= 40%`. That number is currently computed by
three separate copies of the same broken arithmetic — `(pnl or 0) > 0` maps a NULL to "not a win",
and `losses = resolved - wins` then books it as a **loss**. Bot A's true ~33% displays as 12.4%.
Worse: Plan 18-03 starts writing honest `pnl=NULL` rows, and every one of them would land straight in
the loss column of a denominator nobody fixed. The retune's success criterion would be unreadable.

`AIPW_DB_READONLY` rides along because the Phase-17 W1 warning is the other half of the same problem:
any script that imports `src.db` today runs `CREATE TABLE` + `INSERT INTO bots` DDL against whatever
`DATABASE_URL` names. The sweep is about to read prod's baseline knob values.

Output: three one-clause SQL fixes + a two-edit read-only gate. Turns VALIDATION cases 9-13 and 23-25 GREEN.
</objective>

<interfaces>
THE BUG, verbatim (src/db.py:211-229, abridged) — and it is COPY-PASTED into two dashboard routes:

  WHERE bot_id = %s AND status IN ('closed', 'stopped', 'target_hit')
  resolved = len(rows)                                    # counts NULL-pnl AND 0.0-pnl rows
  wins     = sum(1 for r in rows if (r["pnl"] or 0) > 0)  # NULL -> 0 -> not a win
  losses   = resolved - wins                              # every NULL becomes a LOSS

THE FIX, at each of the THREE sites — one clause:
  ... AND status IN ('closed','stopped','target_hit') AND pnl IS NOT NULL

AIPW_DB_READONLY (src/db.py:18-60):
  _pool: ConnectionPool | None = None           # :18 — a MODULE GLOBAL
  _create_pool()  # :21-37  ConnectionPool(conninfo=url, kwargs={"row_factory": dict_row}, open=True)
  get_pool()      # :40-45  if _pool is None: _pool = _create_pool(); _bootstrap_schema()
  _bootstrap_schema()  # :48-53 — executes src/db_schema.sql: CREATE TABLE IF NOT EXISTS + INSERT INTO bots
                       #          i.e. DDL + DML against whatever DATABASE_URL names

  def _readonly() -> bool:
      return os.environ.get("AIPW_DB_READONLY", "") == "1"

  # in get_pool(): if not _readonly(): _bootstrap_schema()
  # in _create_pool(): kwargs={"row_factory": dict_row,
  #                            **({"options": "-c default_transaction_read_only=on"} if _readonly() else {})}

  `options` is a libpq connection parameter psycopg passes through, so it applies to EVERY connection
  the pool hands out and is enforced SERVER-side: any INSERT/UPDATE/DELETE/CREATE raises
  psycopg.errors.ReadOnlySqlTransaction (SQLSTATE 25006). Stronger than a convention.

  TRAP: the flag is read at POOL-CREATION time, not per query. Set it in the process env BEFORE
  src.db is used. Tests MUST reset src.db._pool = None on entry AND exit (RESEARCH P8).
