  and `null_pnl` would never see it (the value is `0.0`, not NULL). A genuine flat trade is
  **indistinguishable** from the sentinel, so **neither is scored**: `pnl == 0.0` → the `zero_pnl` bucket.

  therefore mixes gross and net, and `total_fees` reads **$0 drag for exactly the bots whose P&L is
  overstated**. **NULL `fees` on a counted row is the TELL.** Flag it. Disclose it. **Never subtract fees.**

  def aggregate(rows: list[dict],
                min_sample: int = MIN_SAMPLE,
                key: tuple[str, ...] = ("bot_id", "symbol")) -> list[dict]

Input rows are psycopg3 dict_row dicts (src/db.py:29) as returned by db.get_resolved_trades:
  {bot_id, symbol, asset_class, side, status, pnl, fees, entry_ts, closed_at}
A plain dict fixture IS a row — that is what keeps this testable with zero DB.

Per-cell output fields:
  bot_id (None when not in `key`), symbol (NORMALIZED; None when not in `key`), display, asset_class,
  trades, wins, losses, win_rate, realized_pnl, total_fees, avg_win, avg_loss, expectancy,
  best, worst, first_trade, last_trade, zero_pnl, null_pnl, gross_pnl_rows, null_fees, sample

THE FOUR BUCKETS — a position-closed row lands in exactly ONE. Do not "improve" this:

| Bucket     | Condition       | Counted in trades/wins/losses/realized_pnl/expectancy? | Why |
|------------|-----------------|-------------------------------------------------------|-----|
| win        | `pnl > 0`       | YES (win)                                             | mirrors get_alpaca_accuracy (src/db.py:228) |
| loss       | `pnl < 0`       | YES (loss)                                            | — |
| **zero_pnl** | `pnl == 0.0`  | **NO**                                                | **B1** — indistinguishable from the external-exit sentinel (alpaca_orchestrator.py:167-176). Scoring it as a loss fabricates a losing record on every externally-exited position. |
| **null_pnl** | `pnl is None` | **NO**                                                | a resolution defect; `db.py:228,259` coerce with `or 0` — this must NOT |

Note `null_pnl` and `zero_pnl` are DIFFERENT buckets with different causes. The `or 0` idiom cannot even
distinguish them — which is exactly the bug. Test with `row["pnl"] is None` / `row["pnl"] == 0.0`.

ORTHOGONAL FLAG — `gross_pnl_rows` (B2): a **counted** row whose `fees is None`. Its `pnl` is probably
GROSS. It STILL counts as a win/loss; it contributes 0.0 to `total_fees`; the cell is FLAGGED.

| Rule          | Definition |
|---------------|------------|
| `trades`      | `wins + losses` (excludes zero_pnl AND null_pnl) |
| `realized_pnl`| `sum(pnl)` over counted rows — **NEVER minus total_fees** |
| `total_fees`  | `sum(fees)`, NULL → 0.0 and `null_fees += 1` — **INCOMPLETE drag disclosure** (see gross_pnl_rows) |
| `avg_win`     | `sum(pnl>0)/wins`, `0.0` when wins == 0 |
| `avg_loss`    | `sum(pnl<0)/losses`, `0.0` when losses == 0 — carried **NEGATIVE** |
| `expectancy`  | `win_rate*avg_win + (1-win_rate)*avg_loss` — **INVARIANT: == realized_pnl / trades** |
| `sample`      | `"sufficient"` if `trades >= min_sample` else `"insufficient"` — cell STILL EMITTED |
| zero denoms   | every ratio `0.0`; `aggregate([]) == []`; no ZeroDivisionError |

Reused (do NOT re-derive):
  src.universe.normalize(symbol) -> str   # src/universe.py:17 — the gate's canonicalizer. The group key.

Terminal set (copy from src/db.py:215 — cite it; this repo already has FOUR spellings, do not add a fifth):

  Everything else (rejected/canceled/cancelled/expired/open/submitted) is NOT a trade and is dropped
