<objective>
Add the single read-only query Phase 17 is allowed to run: `db.get_resolved_trades`.

Purpose: SQL selects, Python decides (17-CONTEXT decision 1). This function is the first of two layers
standing between the report and a fabricated loss column: the terminal-status filter here (belt) plus the
pure aggregator's own defence (braces, Plan 03). A `rejected` row carries `pnl = 0`
(`src/bot_thread.py:309,317,332`), and post-Phase-15 the gate emits one per blocked entry; if it reached the
sample it would score as a zero-P&L LOSS against exactly the symbols an operator quarantined, and Phase 18
would quarantine more on that fabricated evidence.

**What this layer CANNOT do (B1):** `src/alpaca_orchestrator.py:167-176` writes `status="closed", pnl=0.0`
for every externally-exited position. That row is *position-closed* — it **passes this filter, correctly**.
SQL cannot tell a sentinel zero from a genuine flat trade. Do **not** try to filter it here (a
`pnl <> 0` clause would also silently drop real flat trades and would hide the defect count). Return it
as-is; **Plan 03 buckets it into `zero_pnl`**.

Output: src/db.py::get_resolved_trades (turns VALIDATION case 14 GREEN; case 16's fence must stay green).
